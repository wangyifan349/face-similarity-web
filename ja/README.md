## 📖 紹介

このプログラムは次のような問題を解決します：**クエリ画像を1枚与えて、それが誰と最も似ているかを見つける。** まず画像中の顔位置を検出し、各顔について固定長の特徴ベクトルを抽出し、2つの特徴ベクトルのコサイン類似度を0–100のパーセントに換算し、最後に類似度の降順で候補リストを返します。パーセントが高いほど、2枚の写真の顔特徴が近いことを意味します。プログラム自体は「同一人物かどうか」の結論を出さず、具体的な判定閾値は利用者が自身のサンプルで別途キャリブレーションする必要があります。

プログラムは2種類の検索方式を提供し、独立して使えます：

- 📤 **アップロード比較** —— クエリ画像1枚を今回一緒にアップロードされた複数の候補画像と1枚ずつ比較します。顔ライブラリを作る必要がなく、一時的な照合に適しています。
- 🗂️ **顔ライブラリ検索** —— クエリ画像1枚をサーバの顔ライブラリの全画像と比較し、最も類似した上位を自動で返します。固定された人物集合から探すのに適しています。

両者はページの左右2列に並べて配置され、視覚レイアウトと操作は完全に同じです。

このリポジトリは2つのエンジン実装を提供します。[2つのバージョンの違い](#-2つのバージョンの違い)に列挙した差異を除き、機能・API・ページの動作は完全に同じで、それぞれ単一ファイルで、検出・特徴・評価・Webサービスのロジックがすべて内蔵され、2つ目のモジュールに依存しません。

## 🔀 2つのバージョンの違い

| 比較項目 | dlib版 | InsightFace版 |
| --- | --- | --- |
| 📄 ファイル | `flask_face_match_v2.py` | `flask_insightface_face_v3.py` |
| ⚙️ 起動設定 | コマンドライン引数 | **無引数**、起動時に対話式で顔ライブラリディレクトリを質問（渡された引数は黙って無視される） |
| 👁️ 顔検出 | `mmod_human_face_detector.dat`（CNN）またはdlib内蔵HOG、ページで切替可 | SCRFD（`det_10g.onnx`）、**単一検出器** |
| 🧬 特徴抽出 | dlib ResNet、128次元 | ArcFace、512次元 |
| 📍 キーポイントモデル | 必要（68点、無い場合は5点にフォールバック） | 不要 |
| 📥 重みの取得 | `.bz2` を手動ダウンロードして解凍 | 初回実行時に `insightface` が自動ダウンロード |
| 📏 スコアの目盛 | 同一人物は概ね85以上 | 同一人物は概ね75以上、別人は0近辺 |
| 🎛️ ページの検出方式ドロップダウン | あり | なし |
| ⚡ ハードウェア加速 | CPU（ローカル検証環境） | 起動時にCUDAを自動探知、使えればGPU、なければCPUにフォールバック |

> ⚠️ **2つのバージョンのスコアは横断的には比較できません。** 全く異なる特徴モデルから出るため、目盛はそれぞれ内部でのみ一貫しています。詳細は[スコアの基準](#-スコアの基準)を参照。

## ✨ 機能特性

| 特性 | 説明 |
| --- | --- |
| 📦 **単一ファイル配置** | 2つのエンジンがそれぞれ1つの `.py` ファイル、第2モジュールなし |
| 🔀 **2つの検索方式** | アップロード比較と顔ライブラリ検索が並列、互いに非依存 |
| 🎛️ **デュアル検出モード** | dlib版は「正確（CNN）」と「高速（HOG）」の間で切替可、評価基準は一致 |
| 🧠 **モデル常駐** | モデルはプロセス内で1回だけ読み込み、モード切替でサービスの再起動は不要 |
| ⚡ **ライブラリキャッシュ** | 顔ライブラリはファイル単位で特徴をキャッシュし、更新時刻で無効化を判定、追加・変更・削除が即座に反映 |
| 🛡️ **耐障害設計** | 破損または顔なしの画像はスキップして記録し、全体の検索を中断しない |
| 📊 **絶対目盛の可視化** | 類似度バーは固定目盛で描画；⚠️ 負数は0%の空バーとして表示されるが、数値は符号付きの実スコアを表示 |
| 🔒 **環境変数なし** | 両バージョンとも環境変数は一切読まない、設定元が明確 |
| 🕵️ **パス非漏洩** | 顔ライブラリディレクトリはサーバにのみ存在し、ページとAPIのいずれにも公開・受け付けしない |

画面の要点：左右2列が等幅で並び、ページ両側にぴったり寄せる；ファイル選択後すぐにサムネイルプレビューを表示；リクエスト中はボタンが読込状態に；最も類似した項目は独立したサマリーブロックで強調；エラーメッセージは閉じられるアラートバーで表示。

両バージョンともFlask、OpenCV、NumPyを共有し、認識エンジンの依存だけが異なります：

| 項目 | 最低要件 | ローカル検証版 |

| Python | 3.9 | 3.14.3 |
| Flask | 3.0 | 3.1.3 |
| opencv-python | 4.5 | 5.0.0.93 |
| numpy | 1.23 | 2.4.6 |

| エンジン | 追加依存 | ローカル検証版 |
| --- | --- | --- |
| dlib版 | `dlib` | 20.0.1 |
| InsightFace版 | `insightface`、`onnxruntime` | 2.0 / 1.30.0 |

Windows、Linux、macOSをサポートします。dlib以外の依存は全てpipで直接インストールできます：

```bash
pip install flask opencv-python numpy
# 選んだエンジンに応じて下記のいずれかを追加：
pip install dlib                  # dlib版
pip install insightface onnxruntime   # InsightFace版
```

> 📝 上表の「ローカル検証版」は実際にインストールして検証した組み合わせです。コード自体は3.9より上の専用構文を使わないため、理論上の下限は `dlib` / `insightface` の利用可能な wheel が決めます。

### 🔨 dlibのインストールについて

dlibは一部のプラットフォームとインタプリタの組み合わせでプリコンパイル済みパッケージがなく、ローカルにC++コンパイル環境が必要です：

| プラットフォーム | 必要な依存 |
| --- | --- |

ソースコンパイルが失敗した場合は、condaチャネルのプリコンパイル済みパッケージを使えます：`conda install -c conda-forge dlib`。

## 🧠 モデルファイル（重みダウンロード）

### dlib版

dlib公式の4つの重みファイルに依存します。**全てdlib公式サイトからダウンロード、登録・ログイン不要。**

| ファイル | 用途 | 要否 | ダウンロード | 圧縮サイズ |
| --- | --- | --- | --- | --- |
| `shape_predictor_68_face_landmarks.dat` | **68点顔キーポイント予測**。顔枠検出後に特徴点を特定し、特徴抽出の入力として使用 | 必須（無ければ5点にフォールバック） | [dlib.net/files](http://dlib.net/files/shape_predictor_68_face_landmarks.dat.bz2) | 約61 MB |
| `dlib_face_recognition_resnet_model_v1.dat` | **128次元顔特徴抽出**。全ての類似度スコアはこの特徴ベクトルで計算 | 必須 | [dlib.net/files](http://dlib.net/files/dlib_face_recognition_resnet_model_v1.dat.bz2) | 約20 MB |
| `mmod_human_face_detector.dat` | **CNN顔検出器**（MMOD）。「正確（CNN）」モードでのみ必要、横顔・小顔・複雑な背景の検出率がHOGより明らかに高い | 任意 | [dlib.net/files](http://dlib.net/files/mmod_human_face_detector.dat.bz2) | 約0.7 MB |
| `shape_predictor_5_face_landmarks.dat` | **5点キーポイント予測**、68点版のフォールバック代替。68点ファイルが無い場合のみ自動で有効、整列精度が下がる | 任意 | [dlib.net/files](http://dlib.net/files/shape_predictor_5_face_landmarks.dat.bz2) | 約5.4 MB |

📌 先頭2点のいずれかが欠けるとプログラムは動きません（起動段階で例外を投げます）。

> ⚠️ `mmod_human_face_detector.dat` が無くても**優雅にフォールバックされません**：デフォルトモードはCNNなので、モデル読込時に捕捉されない `FileNotFoundError` が発生し、Webサービスはウォームアップ段階で終了します。サービスが稼働中の場合、CNNモードへの切替リクエストは **HTTP 500** を返します。CNNモードが不要なら `--hog` で起動してください。

### InsightFace版

`buffalo_l` モデルパッケージ内の2ファイルに依存：`det_10g.onnx`（SCRFD検出）と `w600k_r50.onnx`（ArcFace 512次元特徴）。

**手動ダウンロード不要**：初回実行時に `insightface` がユーザディレクトリの `.insightface/models/buffalo_l` に `buffalo_l` モデルパッケージ全体を自動ダウンロードします。

プログラムは次の順でモデルディレクトリを探し、**そのディレクトリに2ファイル両方ある場合のみ**ヒットとみなします：

1. スクリプト横の `insightface_models/buffalo_l/`
2. スクリプト横の `models/buffalo_l/`
3. スクリプト横の `buffalo_l/`
4. `~/.insightface/models/buffalo_l/`（自動ダウンロードのデフォルト位置）

💡 先頭3つはモデルをプログラムと一緒に配布して完全オフライン実行するためのものです。

📌 あるディレクトリが存在するがそのうち1ファイルが欠けている場合、そのディレクトリは**黙ってスキップ**して次を試します。全ての位置が不完全な場合、自動ダウンロードに切り替わります。**プログラムは「どのファイルが欠けているか」を自発的に教えません。**

オフライン環境では、先にネットのある機器で一度実行してダウンロードを済ませ、`buffalo_l` ディレクトリを丸ごとコピーして上記のいずれかの位置に置けます。

### 📂 dlib重みの配置位置と探索順

プログラムはまず全ての候補パスを集め、その中で最初に使えたファイルを選びます：

1. スクリプト横の `models/` ディレクトリ
2. スクリプトのあるディレクトリ
3. スクリプトのあるディレクトリ配下の任意のサブディレクトリ（再帰探索）
4. `sys.path` の**全ての**ディレクトリ配下の同名ファイル、およびそのディレクトリの `face_recognition_models/models/` 配下の同名ファイル

> 📝 4番目は `sys.path` の順に各ディレクトリを**交互に試行**します、つまり `sys.path[0]/<ファイル>` → `sys.path[0]/face_recognition_models/models/<ファイル>` → `sys.path[1]/<ファイル>` → … であり、先に `sys.path` 全体を走査してからモデルパッケージを探すのではありません。

全ての位置でヒットしなかった場合、プログラムは起動段階で即座に例外を投げ、どのファイルが欠けているかを明確に指摘します。

🔍 **ASCIIパス優先**：候補の中に純粋なASCIIパスがあれば、より前に並ぶ非ASCIIパスよりも優先されます（dlibは非ASCIIパスを開けないため）。全ての候補が非ASCIIの場合は先頭に戻します。

推奨のディレクトリ構成：

| パス | 用途 | 要否 |
| --- | --- | --- |
| `flask_face_match_v2.py` | dlib版本体 | 必須 |
| `models/` | 重みファイル置き場、必須2点はここ | 必須 |
| `face_library/` | 顔ライブラリディレクトリ、`--dir` で他の位置を指定可 | 任意 |

### 🛍 代替の取得手段

dlibの重みを1つずつダウンロードする手間を省きたい場合は、次のいずれかを選べます：

| 手段 | 説明 |

| [face_recognition_models（GitHubソースリポジトリ）](https://github.com/ageitgey/face_recognition_models) | 上記モデルパッケージのソースリポジトリ、重みの原本のダウンロード説明付き |

### 🇨🇳 非ASCIIパスについて

dlibは非ASCII文字を含むパスを直接開けません。dlib版にはこの種の重みファイルを自動でシステムの一時ディレクトリ（`%TEMP%\dlib_face_models\`）へミラーしてから読み込む内蔵ロジックがあり、ユーザは気にする必要がありません。InsightFace版はONNX Runtimeベースでこの制限はありません。

## 🚀 起動方法

### dlib版

コマンドライン引数で設定し、環境変数は一切読みません。デフォルトで同じ位置の `face_library` を顔ライブラリディレクトリとし、5000番ポートから待ち受けます。ポートが使用中の場合は自動で後ろにずらし、最大20個（5000–5019）を試します。

| 引数 | デフォルト | 説明 |
| --- | --- | --- |
| `--dir` | スクリプト横の `face_library` | 顔ライブラリディレクトリを指定、全サブディレクトリを再帰スキャン |
| `--port` | `5000` | 開始待ち受けポートを指定 |
| `--hog` | オフ | ページのデフォルト検出モードを「高速」に設定；ページのドロップダウンでいつでも戻せる |
| `--library-info` | オフ | 顔ライブラリの規模だけ統計出力して終了、Webサービスは起動しない |

```bash
python flask_face_match_v2.py --dir "D:\faces" --port 5000
python flask_face_match_v2.py --library-info          # 先に体检してからリリース
```

💡 `--library-info` は初回デプロイで使うことを推奨します。本番公開前にモデル読込が正常か、顔ライブラリのパスが正しいか、画像と顔の数が期待通りか確認できます。

### InsightFace版

**いかなるコマンドライン引数も受け取りません**——スクリプトは `sys.argv` を全く読まず、渡された引数は**黙って無視**されます（エラーも出ず、ヒントも出ません）。引数が効いたと勘違いしないでください。顔ライブラリディレクトリは起動時に対話式で質問します：

| プロンプト | 説明 |
| --- | --- |
| 初回起動時の質問 | 顔ライブラリディレクトリを入力；そのままEnterでスクリプト横の `face_library` を使用 |
| 入力したディレクトリが存在しない | ヒントを出して再質問 |
| ディレクトリではなくファイルを入力 | ヒントを出して再質問 |
| 非対話ターミナル | 質問せず、デフォルトディレクトリを直接使用 |
| デフォルトディレクトリが存在しない | 自動作成 (`mkdir(parents=True, exist_ok=True)`) |

起動前にモデル読込と一度のウォームアップを完了し、アクセス可能なアドレスを表示します。初回起動では `buffalo_l` モデルパッケージのダウンロードも必要で、所要時間はネットワーク次第です。

## 🔬 動作原理

dlib版の処理パイプライン：

> 🖼️ **入力画像** → RGB配列にデコード正規化 → 顔検出 → 68点キーポイント定位 → 128次元特徴抽出 → L2正規化 → コサイン類似度のパーセント換算 → ソートしてTop-Nに切り詰め

InsightFace版の処理パイプライン：

> 🖼️ **入力画像** → デコード正規化 → SCRFDで顔検出 (`det_size=640×640`, `det_thresh=0.5`) し5点キーポイント出力 → クロップして整列 → ArcFaceで512次元特徴抽出 → L2正規化 → コサイン類似度のパーセント換算 → ソートしてTop-Nに切り詰め

スコアに関するいくつかの説明：

- 📏 スコアは**コサイン類似度パーセント**、すなわち `dot(a, b) × 100` です。同じ画像同士の自身比較は100%です。
- 🔎 **クエリ画像側**は最大値制限をしません：各候補はクエリ画像内の**全ての顔**と比較され、最高スコアがその候補のスコアになります。したがってクエリ画像が複数人の集合写真でも最も似た顔を正常に選べます。
- 1️⃣ **候補画像側**は**面積最大**の1枚の顔のみを比較に使います。
- 📊 結果表のバーはブラウザ側で0–100区間に制限して描画されるため、負数は0%の空バーとして表示されますが、数値ラベルは符号付きの実スコアを表示します。

> 📝 2つのファイルは共に `face_similarity_percent()` ライブラリ関数をエクスポートし、そのシグネチャの多顔デフォルト値は**正反対**です：dlib版はデフォルト `compare_all_faces=False`（最大顔を取る）、InsightFace版はデフォルト `largest_only=False`（最適ペア取り）。この関数は**どのHTTPルートからも呼ばれず**、Web側の動作は上記の規則に従います。

## 📏 スコアの基準

2つのエンジンの特徴モデルは異なるため、スコアは**それぞれ内部でのみ比較可能**で、エンジン間の比較には意味がありません。

| サンプル | dlib版 | InsightFace版 |
| --- | --- | --- |
| 同じ画像の自身比較 | 100.00% | 100.00% |
| 同一人物の別写真（正面切り抜き vs 半身像） | 96.85% | 77.57% |
| 別人（複数サンプル） | 同人より明らかに低い | −3% ~ +1% |

上表はローカル1組のサンプルの実測で、桁違いの差を説明するためのものです。InsightFaceのArcFace特徴は別人間の識別度がより高いため、同人スコアはdlibより低く、別人スコアはゼロに近くなります。どちらが正確という意味ではなく、目盛が違うだけです。

💡 推奨：1つのエンジンを決めたら、実際の業務シーンでの同人/別人サンプルをそれぞれ複数組持って閾値をキャリブレーションしてください。上表の数値をそのまま使わず、2つのエンジンのスコアを同じ一覧に入れてソートしないでください。

## 🎛️ 検出モード（dlib版）

| 比較項目 | 正確（CNN） | 高速（HOG） |
| --- | --- | --- |
| 👁️ 検出器 | `mmod_human_face_detector.dat` | dlib内蔵、重みファイル不要 |
| 🔍 アップサンプリング回数 | 0 | 1 |
| 🧩 適したシーン | 横顔、小顔、複雑な背景 | 正面、均一な照明 |
| ⏱️ 相対コスト | 高 | 低 |
| 📍 キーポイントモデル | 同じ | 同じ |
| 🧬 特徴モデル | 同じ | 同じ |
| 📊 評価ロジック | 同じ | 同じ |

アップサンプリングを1段上げると耗时約4倍になり、同時に小顔の検出率が上がります。そのためCNNモードは0、HOGモードは1を取ります。2つのモードは**顔検出の段階だけが異なり**、その後のキーポイント・特徴・評価チェーンは完全に一致するため、2つのモードのスコアは直接横断比較できます。両モードはそれぞれ特徴をキャッシュします（キャッシュキーに検出モードを含む）。行き来しても顔ライブラリを再エンコードしません。

InsightFace版はSCRFD1種のみで、この選択肢はありません。

## 🗂️ 顔ライブラリ規約

- 📍 **位置**：dlib版は `--dir` またはデフォルトディレクトリで決まり；InsightFace版は起動時の応答またはデフォルトディレクトリで決まり。両者とも全サブディレクトリを再帰走査。
- 🖼️ **形式**：`.jpg` `.jpeg` `.png` `.bmp` `.webp` をサポート、拡張子の大小文字は区別しない。
- 👥 **多顔ファイル（顔ライブラリ検索）**：1枚の画像内の**各顔**がそれぞれ独立した候補を生成し、2枚目から `#2`、`#3` のサフィックスを追加。
- 📤 **多顔ファイル（アップロード比較）**：各アップロード画像は**面積最大の1枚の顔**だけを使い、サフィックスを付けず、1枚に複数の顔があっても候補を分割しない。
- 🏷️ **同名ファイル**：異なるディレクトリの同名ファイルは**アップロード比較**結果で「名前 (1)」「名前 (2)」と区別して表示；⚠️ この重複排除は**顔ライブラリ検索には作用しません**——異なるサブディレクトリの `zhang.jpg` はライブラリ検索では共に `zhang.jpg` として表示されます。
- ⚡ **キャッシュ戦略**：キャッシュキーはファイルの絶対パス、ファイル更新時刻で有効性を判定；画像の更新・追加・削除は次回検索時に自動で反映され、削除されたファイルのキャッシュエントリも同期して消去。dlib版は検出モードもキャッシュキーに入れます。
- 🛡️ **耐障害**：画像の読込失敗や顔未検出時はその項目をスキップ；アップロード比較は `skipped` フィールドに理由を列挙し、顔ライブラリ検索は黙ってスキップします。
- 📊 **進捗出力**：顔ライブラリの画像総数が **20枚以上** の場合、両バージョンともターミナルで1枚ずつ読込進捗を表示（キャッシュヒットした画像も同様）。
- 🏠 **ディレクトリ作成**：InsightFace版は起動時にデフォルト顔ライブラリディレクトリを自動作成；dlib版はディレクトリを作らないので自分で用意が必要。

## ⏱️ 性能参考

以下はこのPC（AMD Ryzen 7 5800H / 60 GB メモリ / Windows / Python 3.14.3）での実測データで、参考用のみ、**性能保証ではありません**。

dlib版、入力は640×480画像：

| 操作 | 耗时 |
| --- | --- |
| モデル読込（HOGモード） | 約1255 ms |
| モデル読込（CNNモード） | 約1049 ms |
| HOG顔検出（640×480） | 約142 ms |
| CNN顔検出（640×480） | 約4625 ms |
| キーポイント + 128次元特徴抽出（顔1枚） | 約287 ms |
| 候補500件 × クエリ1件の類似度計算 | 約0.5 ms |

InsightFace版（このPCで起動時に報告された実行プロバイダはCPUExecutionProvider）：

| 操作 | 耗时 |
| --- | --- |
| モデル読込 + 初回ウォームアップ（ONNXセッション初期化含む） | 約1.7 s |
| クエリ1枚 × ライブラリ3枚エンドツーエンド（1600×1600の大画像、初回はエンコード含む） | 約149 – 676 ms |
| 同上、キャッシュヒット後 | ミリ秒単位 |

いくつかの結論と推奨：

- 🎯 2つのエンジンの性能ボトルネックは共に**顔検出**段階に集中しており、特徴抽出と類似度計算のコストは無視できます。
- ⚡ 初回の大規模顔ライブラリ検索は顕著に時間がかかります；以後リクエストはキャッシュにヒットして通常ミリ秒単位です。キャッシュはプロセス内存にあり、サービス再起動後は無効になります。
- 💡 dlib版は日常的にHOGモードをデフォルトとし、必要な時だけCNNに切り替えることを推奨。CNN検出時間は画像解像度の上昇とともに急速に増えるため、ライブラリ投入前に画像サイズを統一すると効果が大きいです。
- 💡 InsightFace版は検出器の選択が不要；SCRFDは入力解像度に敏感なので、同様に入庫前のサイズ統一を推奨。

> ⚠️ 上記の数値はハードウェア構成・画像サイズ・画像内容によって変わります。デプロイ前に必ず対象環境でベンチマークを行ってください。InsightFaceの各段階の個別耗时は項目ごとに計測していません。

### 🧮 FAISS検索高速化について

このプロジェクトは**FAISSを使いません**。顔ライブラリ検索はNumPyの正確な行列乗算（`ライブラリ内顔数 × クエリ顔数`のコサイン類似度）で処理します。これは意図的な選択です：

- FAISSの `IndexFlatIP` は**正確な**インデックスで、現在の行列乗算結果と完全に一致し、同じことを別実装にしただけで速くはなりません；実測では候補500件の類似度計算自体は約0.5 msで、そもそもボトルネックではありません。
- 真のボトルネックは**顔検出**にあり（上表参照）、FAISSは検出に関与しません。
- FAISSを導入すると約456行の依存とインデックスのライフサイクル管理（追加・変更・削除、同期、永続化）が増えますが、利得はほぼゼロです。

顔ライブラリの規模が**万単位以上**で、検索遅延に本当に詰まっている場合に限り、FAISSの近似インデックス（`IVF` / `HNSW`）に替える価値があります。その際は先に検出の耗时を下げてから、検索が本当にボトルネックか評価するのが正しい手順です。

## 🔌 HTTPインターフェース

2つのバージョンのルートとレスポンス構造は完全に一致します。全てのAPIはステートレス呼び出しです。成功はHTTP 200；失敗は `ok: false` と `error` 記述を含む本体を返し、デフォルトステータスコードは400、リクエスト本体が64 MBを超えると413を返します。

| メソッド | パス | 説明 |
| --- | --- | --- |
| GET | `/` | Webページを返す |
| GET | `/api/library` | 顔ライブラリ規模の統計、**数量のみ返す、ディレクトリパスは返さない** |
| GET | `/api/health` | レディネスプローブ：画像数を数えるだけ、**特徴抽出はしない**、高頻度ポーリング可 |
| GET | `/api/stats` | 実行設定：特徴次元、閾値基準、ライブラリ規模、依存バージョン、欠落モデル |
| POST | `/api/query-set` | クエリ画像と今回アップロードした候補画像の比較（1:N） |
| POST | `/api/query-library` | クエリ画像と顔ライブラリ全量比較（1:N） |
| GET | `/library-image/<相対パス>` | 顔ライブラリの1枚の画像を取得、結果表サムネイル用 |
| GET | `/library-image-download/<相対パス>` | 上と同じだがダウンロードとして返す（`Content-Disposition: attachment`） |

> 📌 画像ルートは**顔ライブラリ内部**の相対パスのみ受け付け、`send_from_directory` が解析。ライブラリディレクトリを抜け出そうとする書き方（`../../` など）は全て拒否（403/404）。ライブラリディレクトリの絶対パスはどのレスポンスにも現れません。

### 🩺 `/api/health`

フォルダ内の画像数を数えるだけで、モデル読込・特徴抽出をしないためコストが極小で、生存/レディネスプローブに適します。`ready` が `true` はライブラリに画像が少なくとも1枚あることを意味します。その画像に本当に顔があるかは実際の検索時にしか分かりません。

```json
{ "ok": true, "ready": true, "images": 128, "detector": "cnn", "descriptor_dimension": 128 }
```

`detector` と `descriptor_dimension` は**dlib版のみ返す**。

### 📊 `/api/stats`

このマシンで**実際に有効**な設定を返し、「同じ画像が2台のマシンでスコアが違う」といった問題の切り分けに使います。フィールドはバージョンにより多少異なり、共通部分：

| フィールド | 説明 |
| --- | --- |
| `descriptor_dimension` | 特徴次元：dlib版 `128`、InsightFace版 `512` |
| `threshold_metric` | 閾値基準、固定 `cosine_similarity` |
| `sort_order` | ソート方向、固定 `cosine_similarity_descending`（大きいほど似ている） |
| `library_images` / `library_faces` | ライブラリ内画像数 / 検出顔数 |
| `max_upload_mb` | 単リクエスト本体の上限（MB） |
| `missing_models` | 欠落しているモデルファイル名リスト、空ならモデル完備 |
| `opencv_version` / `numpy_version` | 依存バージョン |
| `detector` / `dlib_cuda` / `configuration` | **dlib版のみ** |
| `onnxruntime_version` / `onnxruntime_providers` / `model_directory_present` / `model_summary` | **InsightFace版のみ** |

### 🔧 共通パラメータ

| パラメータ | 位置 | 値 | デフォルト | 適用版 |
| --- | --- | --- | --- | --- |
| `top_results` | フォームまたはクエリ文字列 | 整数、1–100の範囲 | 10 | 両バージョン |
| `detector` | フォームまたはクエリ文字列 | `cnn` または `hog` | `cnn` | dlib版のみ |

📌 `top_results` の規則：**欠落または数字でない → 10**；整数として解析できたら → **境界で切り詰め** 1–100（`0` → 1、`999` → 100）。

> ⚠️ 両バージョンはここに細かな差異があります：dlib版は `int()` で解析（`+5`、前後空白などを受理）、InsightFace版は `str.isdigit()` で判定してから変換（`+5`、負号、Unicode数字を受理しない）。`top_results=-1` を渡すと、dlib版は1件、InsightFace版は10件を返します。通常ページから送るリクエストは影響を受けません。

> ⚠️ dlib版の `GET /api/library` はクエリ文字列の `detector` を読むため、**同じURLでも検出モードによって返る `faces` 数が変わります**；InsightFace版はこの引数を無視します。

### 📤 アップロード比較（`/api/query-set`）フォームフィールド

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `query` | ファイル | はい | クエリ画像、単枚 |
| `candidates` | ファイル（複数値可） | はい | 候補画像、複数可 |

### 🗂️ 顔ライブラリ検索（`/api/query-library`）フォームフィールド

| フィールド | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `query` | ファイル | はい | クエリ画像、単枚 |

### ✅ 成功レスポンスフィールド

| フィールド | 説明 |
| --- | --- |
| `ok` | 成功かどうか |
| `mode` | 検索モード、`query-set` または `query-library` |
| `query` | クエリ画像ファイル名 |
| `query_faces` | クエリ画像で検出した顔の数 |
| `detector` | 今回実際に使った検出モード（**dlib版のみ返す**） |
| `count` | 今回提出した候補画像の総数（**アップロード比較のみ**） |
| `compared` | 特徴抽出に成功して比較に参加した候補画像の数（**アップロード比較のみ**） |
| `library_images` | 顔ライブラリの画像総数（**顔ライブラリ検索のみ**） |
| `library_faces` | 顔ライブラリで検出した顔の総数（**顔ライブラリ検索のみ**） |
| `matches` | 順位結果リスト、`rank`、`kind`、`candidate`、`similarity` を含む、先頭項に `best: true` 付き |

`kind` フィールドの値：`query-set` は「候補画像」、`query-library` は「ライブラリ候補」。

> 🖼️ `matches` の各行には `image_url` が付くことがあります：その行の写真の `/library-image/` 下のアドレスを指し、ページがサムネイル表示に使います。**顔ライブラリ検索（`query-library`）の行だけに付きます**；アップロード比較の候補画像は対応するファイルがないためこのフィールドは現れません。

## 🔒 セキュリティとプライバシー

- ⚠️ **このプロジェクトは身元判定の結論を提供しません。** 類似度の値だけを出力します。「同一人物かどうか」の閾値選択とそれによる誤判定の責任は利用者が負います。
- 🌐 **サービスはデフォルトで `0.0.0.0` にバインド**され、同じLAN内の他のホストから全てアクセス可能です。ローカルのみに制限するには、ファイル末尾の `app.run(...)` で `host` を `127.0.0.1` に変更してください。⚠️ 注意：ターミナルに表示されるアドレスは常に `http://127.0.0.1:<port>` です。実際には全ネットワークインタフェースにバインドしていても同様です——公開範囲の判断に使わないでください。
- 🧠 **アップロード画像はディスクに保存されません**：メモリ上でのみデコード・計算され、プロセス終了で解放されます。顔ライブラリ画像は読み込まれプロセス内存にキャッシュされます。
- 🕵️ **顔ライブラリパス非漏洩**：ページとAPIのいずれも表示・受付せず、パスはサーバプロセス内部にのみ存在（`/api/library` は数量のみ返す）。結果表サムネイルは `/library-image/<相対パス>` 経由で、ライブラリ内相対パスのみ公開し、`send_from_directory` はライブラリディレクトリを抜ける任意のパスを拒否します。
- 🕳️ **認証機構なし**：プログラムに身元認証とアクセス制御は内蔵されていません。信頼できないネットワークに配置する場合は、必ずリバースプロキシ層で認証を補ってください。
- 🐌 **ネットワーク共有ディレクトリを顔ライブラリにするのは非推奨**：小ファイルが大量のネットワークI/Oは性能を顕著に劣化させます。
- ⚠️ **内蔵サーバはFlask開発サーバ**で、イントラネットの小規模用途に限ります。本番はGunicorn、uWSGI等のWSGIサーバの後ろに置いてください。

## ⚠️ 既知の制限

- 🚫 顔検出結果のクロップ・回転補正などの顔整列強化は提供しない：dlib版はデフォルトキーポイント予測のみ、InsightFace版はSCRFD自带の5点整列を使用。
- 💾 特徴キャッシュはプロセス内存にあり、サービス再起動後はライブラリ全体の再エンコードが必要。
- 📏 特徴はそれぞれdlib ResNet（128次元）とArcFace（512次元）由来で、他の顔認識手法のスコアと**直接比較できない**；2つのバージョン間も比較不可。
- 👥 アップロード比較では各候補画像から面積最大の顔だけを取り、集合写真の他の人物は独立候補にならない（顔ライブラリ検索は各顔を展開する）。
- 🚫 バッチオフライン比較APIと結果の永続化機能は提供しない。
- ⚡ ハードウェア加速を手動指定できない：dlib版はローカル検証環境でCPU動作；InsightFace版は起動時に `CUDAExecutionProvider` を自動探知し、使えればGPU優先、なければCPUフォールバック。利用者は引数で実行デバイスを強制指定できない。
- 🐛 InsightFace版は `top_results` の異常なUnicode数字（例：`²`）の処理が不安定で、捕捉されない例外が出る可能性がある。

## ❓ よくある質問

**❌ dlib版起動時に `.dat` 重みファイルが見つからないと出る**
モデルがプログラムの探索可能な位置にありません。[モデルファイル](#-モデルファイル重みダウンロード)章を参照してファイルを配置するか、`face_recognition_models` モデルパッケージをインストールして先頭2つの必須重みを解決してください。

**❌ InsightFace版起動後にモデルが再ダウンロードされた**
スクリプト横の3つの `buffalo_l` ディレクトリと `~/.insightface/models/buffalo_l` が共に `det_10g.onnx` と `w600k_r50.onnx` を同時に含んでいないことを意味します——不完全なディレクトリは黙ってスキップされます。ファイルの完全性を確認するか、引数なしで起動してログを見てください。

**❌ 「顔ライブラリに画像がありません。画像を入れてから再試行してください」と出る**
顔ライブラリディレクトリが存在しないか、対応する画像形式が含まれていません。dlib版は先に `--library-info` で確認；InsightFace版は再起動してプロンプトで正しいディレクトリを入力。

**❌ 「クエリ画像から顔を検出できませんでした」と出る**
現在の検出器が顔を見つけられていません。dlib版は「正確（CNN）」モードに切り替えて再試行を推奨——CNNは横顔と小顔に寛容です。同時にアップロードしたのが元の写真か、スクリーンショットの部分切り抜きでないか確認してください。

**❌ 「顔ライブラリから顔を検出できませんでした」と出る**
顔ライブラリに画像はあるが全て顔未検出。実際の検出数を先に確認し、画像の鮮明さとサイズを抜き取り確認してください。

**❓ 初回の検索が遅く、以降は速い**
期待通りの動作。初回はライブラリ全体のエンコードが必要で、結果をキャッシュすれば以後はミリ秒単位。

**❓ ポートが使用中**
両バージョンとも最大20個のポート（5000–5019）を自動で後ろにずらします。ターミナル出力の実際のアドレスを基準にしてください。

**❓ 画像を差し替えたのに検索結果が変わらない**
起こるはずがありません。キャッシュはファイル更新時刻で判定するので、ライブラリ内の同じパスのファイルを変更したか確認してください。

**❓ 顔ライブラリに同名の2枚の画像が共に `zhang.jpg` と表示される**
現在の実装です。「名前 (1)」「名前 (2)」の重複排除は**アップロード比較**の結果にのみ作用し、顔ライブラリ検索は重複排除しません。

**❓ 重みファイルが非ASCII文字を含むパスにあっても使えるか**
使えます。dlib版は自動でモデルをシステム一時ディレクトリにミラーして読み込みます；InsightFace版にこの制限はありません。プログラムは複数の候補パスから純粋ASCIIを優先します。

**❓ なぜある候補にスコアがない/結果に現れないのか**
その画像の読込失敗または顔未検出。アップロード比較のレスポンスの `skipped` フィールドに理由が列挙されます；顔ライブラリ検索は黙ってスキップし、`--library-info` で画像数と顔数を対比できます。

**❓ 2つのバージョンのスコアを一緒に比較できるか**
できません。[スコアの基準](#-スコアの基準)を参照してください。目盛が異なるのでそれぞれ閾値をキャリブレーションする必要があります。

**❓ LAN内の同僚がこのページを開けない**
両バージョンともデフォルト `0.0.0.0` にバインドされ理論上アクセス可能；接続できない場合はOSのファイアウォールがそのポートを許可しているか確認してください。
